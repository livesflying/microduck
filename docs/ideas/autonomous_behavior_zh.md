# 自主行为堆栈 — 它所继承的，以及等待它的想法

大脑是parity审计中的最大未跟踪缺口([parity审计] §03)：运行时的`autonomous.rs`在守护进程中不存在，也没有设计文档拥有它。这个文件是过渡区 —— 这个部分需要涵盖的内容，以及来自theremin/chorale工作(2026-08)中的想法，应该作为堆栈中的*行为*存在，而不是更多的临时模式。

[parity审计]: https://claude.ai/code/artifact/4ea45b32-a298-42ea-bcb4-1d2a7a567948

## 从运行时进行移植（审计 §03）

一个16状态机 —— 冷静、环视、漫游、原地旋转、兴奋、惊吓、伸展、梳理、打喷嚏、跳舞、地面拾取、小憩、玩球、被抚摸、被抱持 —— 建立在：

- 一个**能量/情绪模型**驱动状态选择
- **漫游的新颖性网格探索记忆**
- **ToF障碍物避免**，带有新鲜度门控
- 基于对比的**惊吓**；**声音反应**（噪音 vs 语音）带有自我音频 / 自我运动门控
- **玩球**（接近 / 排队 / 踢球），一个**小憩周期**，**抚摸反应**
- 进程中的游戏手柄↔自主切换（DpadRight 2 s），`--autonomous-max-speed`

它的所有输入现在都存在于守护进程中：环境声音事件（步骤2 —— 记录，没有消费者），深度帧（步骤3），分类的主干帧障碍点（步骤5），以及语音标签（步骤2，"准备好进行大脑步骤"）。`Held`依赖于拾取检测，该检测已弃用 —— 决定是否恢复该状态或删除该状态。

## 大脑免费获得的新输入（2026-08工作）

theremin/chorale步骤构建的，运行时大脑从未有过的：

- **附近的鸭子，通过稳定ID标识** —— 节奏合唱的信标（`ChoraleBeacon`），它能生存于BLE地址旋转（参见`docs/../memory`：从不基于地址进行键值化）
- **一个共享的节拍**，没有时钟同步（`sounds::chorale::beat`） —— 跨鸭子范围±20 ms
- **每个广告的RSSI** —— 免费粗略距离（近 / 远 / 接近）
- **约245个额外字节**的扩展广告负载
- **一个实时合成音**（`sounds::Stream`）：运行时的音高/音量/元音，而不仅仅是音库wav
- **手部距离ToF**（`kinematics::hand::Tracker`）

## 行为想法，大致按魅力/行数排序

**社交（BLE存在 —— 新的领域）：**
- **识别与问候** — 保持一个已遇见鸭子id的持久列表；`greet`一个陌生人，对朋友发出更温暖的声音，当朋友的信号消失时发出`啄击`或叹息。友谊作为一种相遇次数的变化，随着时间改变问候方式。读作*记忆*；无需同步。
- **孤独/满足** — 一只鸭子独自时会偶尔发出叫声；有同伴时则不会。这是情绪模型的一个输入，而不是一种状态。
- **接近时的兴奋** — 对于已知id的RSSI上升 → 可见的期待。
- **马可波罗游戏** — 一只鸭子隐藏，另一只通过加快叫声频率引导你，随着RSSI增加。
- **跟随者** — RSSI保持间距，ToF处理前方的鸭子。
- **掌声/社会反馈** — 一只鸭子做了一个滚翻，附近的鸭子作出反应。
- **电话** — 一条消息通过空闲载荷从一只鸭子传到另一只鸭子，发生变异。
- **投票** — 在信标载荷中的偏好；多数决定群体的下一步行为。

**同步运动（在同步工作的地方兑现价值 — 无需扬声器）：**

- **群体点头/摇摆** — 所有鸭子在共享节拍上同步；视觉同步可以容忍约50毫秒的误差，而音频需要20毫秒。在乐句的强拍上形成群体姿态。类似康加线。
- **舞蹈**（已经是一个运行时状态）在有同伴时成为*同步*舞蹈。

**音乐性，超越和声：**

- **呼唤与回应** — 对位的乐句；乐句之间的间隔隐藏了同步误差，因此比和声更容易实现，更符合鸭子的行为。
- **一个圆圈** — 同一旋律，有意识的多小节偏移；这些偏移吸收了误差。
- **每个角色一个** — 音型 + 节奏啄击 + 主旋律。小扬声器在纹理上表现更好，而不是和声。

## 鸭子检测器（相机 + NPU）—— 招募中，等待媒体

一个专为*我们自己的鸭子*设计的单类检测器：精确的**方位**用于注视和跟随，而ToF和BLE无法提供。RK3566具有0.8 TOPS INT8 NPU（`rknpu2` / `rknn-toolkit2`）；一个输入为320的YOLOv8n/11n级模型应在约20–40毫秒内运行 → 15–30赫兹，从而让CPU得以清闲。范围计算：IMX219水平视场角约为62°，一只25厘米的鸭子在3米处约为25像素 —— 这是交互范围，即互动的边界。
- **Gate 先来:** 板上的 NPU 驱动是 `rknpu` 吗？(`dmesg | grep -i rknpu`) — 供应商内核 `rknpu2`，不是主线。并且 `/dev/rga` 用于免费的 NV12 缩放。请媒体层从 ISP 主路径分流原始 NV12；检测器必须不要解码流 MJPEG。
- **数据是项目，不是模型。** 鸭子视角的视频（机器人高度，机器人相机）由一个大容量开放词汇模型自动生成标注，提炼成小型模型；合成渲染来自 Open Duck CAD 的尾巴；硬负样本（橡胶鸭子，白色打印品）。
- **融合:** 视觉无法区分相同的鸭子 —— 摄像头 = 方向，ToF = 距离，BLE 信标 = 身份 + 存在。跟随者使用所有三种信息；“做事时互相看着” = 信标说 *何时*，检测器说 *何地*，`robot.look` 完成其余部分。
- 同 `tofd`/`pet-detect` 的架构：一个感知工作者在 `robotd` 之外，可以安全地杀死。在媒体层移植时（审查 §04 TODO）修复 IMX219 的固有参数。

## 形状注记

- 存在、情绪和共享节奏是 **一个大脑** 的输入，而不是旁边的不同模式 —— 芝加罗/ theremin 模式显式增长，因为没有大脑可以挂载它们；当它落地时，将其作为状态/输入折叠进来（“宠物”对 pet-detect 之于“唱”就像听到信标之于“唱”）。
- **芝加罗最终成为自发事件，而不是命令。** `robotctl chorale` 是实验支架：一旦鸭子自主运行，一群鸭子有时应该在公司存在（并可能在情绪/能量上）的情况下 *有时* 自发地唱起来 —— 低概率随机事件，类似于 Zoomies 或 Dance Fire，不是用户启动的。很少发生是故意的：惊喜二重唱令人愉快，而自动点唱机则不然。机制几乎不变 —— 一个空闲信标鸭子已经知道附近谁，所以“决定唱歌”只是一个更多状态转换；`[chorale] accept` 保持为是否任何鸭子可以加入的同意门。
- 芝加罗的同意规则泛化：**任何社交活动都是可选的，关闭 = 不可见**（今天 `[chorale] accept`；明天可能有一个 `[social]` 开关）。
- 识别/问候是正确的 *第一* 行为：每行最高魅力，无需同步，并且它锻炼了 BLE 发现层 —— 仍然在硬件怀疑之下的一部分。
